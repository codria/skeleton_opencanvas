# 機能要件定義：AIスケルトン体験デモ

## 実装する機能（Goals）

### F-01：リアルタイム骨格推定
- カメラ映像から人体の骨格をリアルタイムで推定する
- MediaPipe Pose Landmarker（新 API）を使用し、`num_poses` パラメータで複数人検出を試みる（目安：1〜3 人）
- ランドマーク座標は指数移動平均（EMA）で平滑化する（係数 α はランタイム調整可能）
- 推定ライブラリ：mediapipe（Pose Landmarker）

### F-02：モード1 ― オーバーレイ表示
- カメラ映像をそのまま背景として表示する
- 検出した骨格を線と点でリアルタイムに重畳描画する
- 複数人分の骨格を同時に描画する（F-01 のフォールバック方針に準ずる）

### F-03：モード2 ― マネキン表示
- 設定ファイルで指定した固定の風景写真を背景として表示する
- 背景画像は画面いっぱいにクロップ表示する（中央基準・レターボックスなし）
- 骨格データをもとにマネキン（関節：球、骨：テーパード円柱、胴体：角丸プリズム、頭部：楕円体、首・指：円柱）を 3D 描画する
- マネキンはカメラ映像のアスペクト比に合わせたビューポートで描画し、モード1と人物の位置・スケールが一致するようにする
- 実写カメラ映像を半透明オーバーレイとしてマネキン上に重ねられる（透過度ランタイム調整可能）
- 複数人分のマネキンを同時に描画する（F-01 のフォールバック方針に準ずる）
- 背景画像はファイルパスの変更のみで差し替え可能とする
- マネキンの太さ／サイズはスライダー（および +/- キー）でランタイム調整可能とする

### F-04：モード3 ― 3D キャラクター表示
- 3D 空間（床・柱・壁）を背景として描画する
- 視点を自動回転させ、スライダーで回転速度・視点角度をランタイム調整できる
- 骨格データに連動して動くマネキン（プリミティブ または GLTF メッシュ）を表示する
- pose_world_landmarks（実 3D 座標）を活用し、奥行きを伴った姿勢を再現する
- キャラクターデザインは GLTF ファイルの差し替えで対応する（`assets/characters/`）
- 実写カメラ映像を半透明オーバーレイとして重ねられる
- 複数人対応を試みる（F-01 のフォールバック方針に準ずる）

### F-05：モード切り替え
- キーボード `1` / `2` / `3` キーで各モードをその場で切り替えられる
- GUI のボタンからも切り替え可能
- 切り替え時もカメラキャプチャは継続し、映像が途切れない

### F-06：アプリ起動・終了
- コマンド一発でアプリを起動できる
- `Q` キーまたは `Esc` キーでアプリを終了できる
- 終了時に現在のパラメータを `user_settings.json` に自動保存する

### F-07：設定ファイル
- 背景画像パス、カメラデバイス番号、解像度、FPS、ポーズパラメータ初期値など、環境依存のシステム設定は `config.yaml` で管理する
- コードを変更せずに設定を切り替えられる
- ダイアログ等で変更した値はランタイム上書きで即時反映できる（ファイルへの書き戻しは行わない）

### F-08：GUI コントロールパネル
- PyQt6 製のウィンドウ上にカメラ映像・描画結果を表示する
- モード切り替えボタン、動画選択ボタン、カメラ復帰ボタン、背景選択ボタンを GUI 上に配置する
- 左カラムに「検出人数／平滑化α／グラフサイズ／軌跡（点・線・長）／実写透過／太さ（Mode2）／回転（Mode3）」のスライダーを配置する
- スライダー値は `AppSettings` で一元管理し、`user_settings.json` で永続化する

### F-09：画面上の操作ガイド表示
- 現在のモード名を左上に常時表示する
- キー操作の説明を画面右下（ボタンパネルの上）に常時表示する
- デバッグ情報（FPS・人数・描画解像度）をモード名の下に常時表示する
- `H` キーでモード名・操作ガイド・デバッグ・スライダー群を一括 ON/OFF できる（グラフは独立、`G` キーで個別 ON/OFF）
- 表示位置・サイズはデモの邪魔にならないよう配慮する

### F-10：起動時のカメラ確認
- 起動時にカメラへの接続を確認し、映像が取得できているかを検証する
- カメラが見つからない・映像が取得できない場合はエラーメッセージを表示してアプリを安全に終了する

### F-11：動画ファイル再生（追加）
- `V` キーまたは GUI ボタンで動画ファイルを開ける
- `C` キーで再びカメラ入力に戻れる
- 動画再生中は画面下部に再生コントロールバー（停止／シーク／時刻表示／ループ／速度／書出／サンプル書出）を表示する
- 再生速度は 0.5x / 1.0x / 2.0x / 3.0x / 5.0x / 10.0x を循環選択できる
- シーク時に時系列グラフ・トレイル・推定器のタイムスタンプを連動リセットする

### F-12：動画 MP4 書出（追加）
- Mode2 の描画結果を入力動画と同じ解像度・FPS で MP4 として書き出せる
- ボーンオーバーレイ（B キー有効時）と時系列グラフ（右上）も焼き込む
- 「動画書出」「サンプル書出（先頭 300 フレーム）」の 2 ボタンを提供する
- 書き出した MP4 に元動画の音声トラックを ffmpeg で mux する
  - ffmpeg は PATH または Shotcut/Krita/OBS の同梱版を自動検出する
  - 検出できない場合は無音 MP4 のままで出力する（警告ログのみ）
- 書出中はキャンセル可能なプログレスダイアログを表示する

### F-13：時系列グラフ（追加）
- 両手両足（手首・足首）の正規化 X・Y 座標を、過去 10 秒分のラインチャートとして画面右上に 2 枚（X 用・Y 用）表示する
- グラフサイズ係数はスライダーで 0.3〜3.0 倍の範囲で調整できる（軸ラベル・目盛フォントも連動）
- カメラ入力時は経過時間（`perf_counter`）、動画ファイル時は動画内時刻（`frame_idx / source_fps`）を X 軸に使う
- 認識失敗フレームは折線を切る（NaN 挿入）
- `G` キーで表示／非表示を切替可能（`H` キーとは独立）

### F-14：トレイル（軌跡）（追加）
- 両手両足の移動経路を色分けで残す（左手首：シアン、右手首：マゼンタ、左足首：ライム、右足首：オレンジ）
- 認識成功フレームでは現在位置に丸点、過去軌跡を半透明線で描く
- 認識失敗フレームでは点・線とも一斉に消える（連続性のジャンプを防ぐ）
- 点サイズ／線太さ／保持点数をスライダーで調整可能
- マネキン本体表示と独立に ON/OFF 可能

### F-15：パラメータ永続化（追加）
- 検出人数・平滑化α・グラフサイズ・グラフ可視・ボーン表示・トレイル設定・実写透過・Mode2 太さ・Mode3 回転速度／視点角度を `user_settings.json` で永続化する
- 起動時に load して各 UI・Renderer・Estimator に反映、終了時に save する
- ファイル不在・破損時はデフォルト値にフォールバックする
- `user_settings.json` は git 管理外（端末ごとの個別設定）

## 実装しない機能（Non-Goals）

- スクリーンショット保存機能
- BGM 再生（書出に元動画音声を含めるのみ）
- ネットワーク通信・クラウド連携
- GUI 設定画面（システム設定は `config.yaml` 編集、ユーザー調整値は UI スライダー）
- スマートフォン・タブレット対応
- インストーラーの作成（スタッフが手動でセットアップする前提）
- 異常終了時の自動復旧（再起動による手動対応を Runbook に記載する）

## 技術スタック

| 用途 | 技術 |
|------|------|
| 骨格推定 | MediaPipe Pose Landmarker（新 API） |
| GUI フレームワーク | PyQt6 |
| 3D 描画 | PyOpenGL（PyQt6 + QOpenGLWidget） |
| カメラ・動画 I/O | OpenCV（opencv-python） |
| 時系列グラフ | pyqtgraph |
| 動画書出の音声 mux | ffmpeg（外部実行ファイル、Shotcut 同梱版等を自動検出） |
| 設定ファイル | PyYAML（システム設定） / JSON（ユーザー設定） |
| 数値計算 | NumPy |
| 言語 | Python 3.10 以上 |

## スコープ補足

- 実行環境は Windows ノート PC を第一ターゲットとする
- 軽量動作を優先するため、描画は内部 FBO 1280x720 固定でレンダリングしてウィンドウサイズに描画コストを依存させない
- 複数人対応は `num_poses` で試み、品質・パフォーマンスが不十分な場合は 1 人専用にフォールバックする
- カメラ映像はアスペクト比を維持して表示する（レターボックス）
- ボタンパネルは GLWidget 上にオーバーレイ表示し、映像表示領域はウィンドウ全体を使用する
- 動画書出は処理時間が長い（書出元動画 1 分につき数分）。サンプル書出（先頭 300 フレーム）で挙動確認できるようにする
